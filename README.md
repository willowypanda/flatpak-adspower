# flatpak-adspower

Convert the AdsPower Global `.deb` package into a Flatpak bundle, with automated updates and a GitHub Pages repository.

## Goal

This repository is organized so that it can eventually be submitted to Flathub. For now it:

- Downloads the latest AdsPower Global Linux `.deb` from `https://www.adspower.com/download`.
- Extracts the version from the filename.
- Builds a Flatpak bundle using `flatpak-builder`.
- Publishes the bundle to a GitHub Release.
- Updates the repository's GitHub Pages site with the latest download information.

## Build manually

```bash
cd flatpak-adspower
./install-prereqs.sh
./download-latest.sh
./build-flatpak.sh
```

## GitHub Action

The workflow `.github/workflows/build.yml` runs on a schedule and can be triggered manually. It:

1. Downloads the latest `.deb`.
2. Compares the upstream version to existing release tags.
3. If a new version is found, builds and releases a new Flatpak bundle.
4. Updates `docs/` for GitHub Pages.

Release tags use the format `v<adsversion>-<pkgrev>`:

- `<adsversion>` is the upstream AdsPower version.
- `<pkgrev>` starts at `1` for each upstream version and is incremented when packaging changes.

If you need to rebuild for the same upstream version, use `workflow_dispatch` and set `force_build` to `true`. You can optionally set `force_pkg_rev` to a specific revision number.

## GitHub Pages

Enable GitHub Pages in the repository settings and point it to the `docs/` folder on the default branch. The Pages site will display the latest release download link.

Because Flatpak bundles can exceed 100 MB, the bundle itself is attached to GitHub Releases rather than committed directly to the repository. Pages only hosts small HTML/flatpakref files.

If you prefer to commit bundles to the repository, enable Git LFS for `*.flatpak` files and add a `.gitattributes` entry:

```gitattributes
*.flatpak filter=lfs diff=lfs merge=lfs -text
```
